## E. Corrected interpretation

Test 7 does **not** demonstrate source verification. In the current
implementation it is rejected, if at all, because the changed component value
disagrees with the derived `gene_intact_all` field. That is an internal-
consistency check. The validator does not resolve the citation, retrieve the
cited source, or compare the altered value against source evidence.

Changing both the value and the citation makes no difference to the outcome,
because the citation is never resolved. The resulting row is internally
consistent and simply passes.

## F. Harness defects found and fixed

Two defects, both in `tools/test_provenance_adversarial.py`, both confirmed by
execution before fixing. Neither changed the conclusion — but the first one
invalidated the *previous* run's fidelity, so it is recorded rather than
quietly repaired.

### Defect 1 — naive `split(",")` on an unquoted CSV

Shipped `source` fields contain commas (e.g. `Emerling 2021: 'all 13
crocodylians ...'`). A naive split yields more fields than the header, and
`csv.DictReader` mis-assigns columns. **Fixed**: the harness now round-trips
reading *and* writing through the csv module.

Added case 8 (a citation containing commas and embedded quotes) to prove the
round-trip holds. Before the fix this class of mutation would have landed in
the wrong column.

### Defect 2 — mistyped column name in the test itself

I wrote `GENES = [..., "MTNR1B_intain"[:7]]`. The slice produced
`MTNR1B_intain`, a column that does not exist, so `DictReader` returned `None`,
`(None or "")` became `""`, and **every flag-domain check silently passed**.

Detection was accidental: the control line printed
`[control] shipped CSV -> {'INTERNAL_CHECK'}` — the *shipped, correct* data
appearing to fail. A red control is easy to misread as "the data is bad" rather
than "the harness is wrong"; I checked the data directly against the correct
column names and found zero violations, which located the fault in the test.

**Fixed** the name, and added `_assert_columns_known()`, which raises at import
if any name in `GENES` is absent from the CSV. Verified the guard fires:

```
AssertionError: GENES contains column name(s) absent from the CSV:
['MTNR1B_intain']. Available: ['AANAT_intact', 'ASMT_intact', ...]
EXIT CODE: 1
```

### Checked and found sound

`build_datasets.py` — the production validator — references all four gene
columns correctly. The defect class was confined to the test.
